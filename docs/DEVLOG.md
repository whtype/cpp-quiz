## 为什么有两套界面

小程序端（`pages/`）和浏览器端（`preview.html` + `web-*.js`）是**独立实现**，不是编译产物。原因：

- 小程序没有构建工具，浏览器版要能直接 `file://` 打开、能挂 GitHub Pages
- 浏览器版能用 localStorage 做持久化，小程序用 `wx.setStorageSync`
- 两边的存储层被抽成同一组接口（`utils/store.js` / `web-storage.js`），题库和判分逻辑共用 `data/questions.js`

代价：**改 UI 要改两处**，`GPT-BRIEF.md` 里已经写成硬约束。

## 几个关键决策

### 题库不打包开源题（v2.1）

包体从"几百 KB 开源题"改成"600 道自写的中文题 + 运行时从 CDN 拉"。这样改题库不用重新发版，包体也可控。拉取失败不影响使用。

### 练习的三个行为（v2.6）

用户明确要求：退出要能续做、题数要能选、没作答要能跳过。

实现要点：进度只存**题目 id 列表**不存题面（题库换源后按 id 回查，查不到就由 `store.prune()` 清掉）。`resumable()` 的判据是 `0 < idx < len-1`——答到最后一题就不该再问"要不要继续"。

这三条在 v2.7 按章节重构后仍然成立，`tools/test-resume.js` 16 项断言守着。

### 按章节练习（v2.7）

首页从"四个方格入口"改成"一句话 + 今日练习卡"，选题数收进 `pages/learn`（章节 + 三档难度）。少一次选择，进来就能刷。

### 网页版深链约定

```
#practice / #practice-algo / #practice-wrong / #exam / #random  → 直接进答题
#wrong / #fav                                                  → 进错题本列表（对应 tab）
?pick=seq-algo   直接弹选题浮层
?resume=1        显示续做条
?still=1         关掉过渡动画（截图用）
```

`#wrong` 早先被路由成"错题重练"，导致列表页打不开、验收时看着像丢了页面。现在分开了。

## 踩过的坑（都已在 check.js 里加了守卫）

1. **导航栏返回键点不动**（v2.4）— 全局 `box-sizing:border-box` 把 `padding-top` 吃进 `height`，内容区压成 0，返回键被顶进状态栏，灵动岛机型必现。`.nav` 必须 `content-box`。
2. **错题本点进去全空**（v2.5）— 题目 id 索引只在 `setExtra()` 里建，没有在线缓存时 `MAP` 恒空。必须模块加载时就 `rebuild()`。
3. **选项显示成「A A」**— 题目 `options` 只写了字母，内容藏在 `code` 里。`check.js` 现在会拦。
4. **`project.config.json` 非法 JSON**（v2.7）— 忽略项被误塞进 `setting.babelSetting.ignore`，末尾还多一个逗号。开发者工具直接读不了项目，而所有 JS 检查照样全绿。`check.js` 第 9 组现在全量校验 json。
5. **Chrome 截图假象** — `--window-size=390,844` 实际视口是 512（有最小窗口宽度），截出来像"页面在手机上溢出"。要用 `tools/shot-mobile.js`（DevTools 协议强制视口）。

## 已知限制

- **题库事实准确性没有自动校验**：`audit-bank.js` 只查结构（重复、空解析、答案越界），判断不了"这道题的技术结论对不对"。v2.7 新增的 150 道题是 AI 生成的，抽查过 6 道都正确，但没逐题复核。
- **网页版数据不落服务器**：记录在 `localStorage`，换浏览器 / 清缓存就没了，也不能跨设备。
- **`github.io` 在国内时好时坏**：微信里打开可能被拦，让用户复制到手机浏览器。
- **小程序端还没真正跑过真机**：开发者工具能编译，但因为没上传，体验版还没验证。
